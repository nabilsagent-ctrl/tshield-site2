## What this is
The **LIVE T-Shield marketing website** — the public brochure site for T-Shield (interior surface protection + automotive PPF), part of Topaz Detailing Group. Production domain: **www.t-shield.co**. It is **LIVE in production and public-facing — ship carefully.** A broken page here is visible to every prospect and franchise lead.

## Stack
- **Type:** **Static site** — plain HTML + CSS + vanilla JavaScript. No framework, no bundler, no React/Next, no npm runtime dependencies.
- **Build step:** one tiny Node script. `npm run build` runs `node scripts/build-hubspot-config.js`, which regenerates `config.js` from the `HUBSPOT_PORTAL_ID` env var. That's the entire build — no compilation, no transpile.
- **Hosting:** Vercel — auto-deploys from the `main` branch (~1 min after merge). Preview URL `tshield-site2.vercel.app`; production domain `www.t-shield.co`.
- **Headers/caching:** `vercel.json` sets security headers (HSTS, X-Frame-Options DENY, etc.) and long cache on assets / no-cache on HTML. Touch with care.
- **Integration:** HubSpot forms/UTM capture, switched on by setting `HUBSPOT_PORTAL_ID` in Vercel (zero-commit activation — no env var = tracking off, `config.js` writes `null`).

## Build / test / deploy
Full no-AI detail in `HUMAN_RUNBOOK.md`. In short:
1. No install needed to view — just open `index.html` in a browser, or serve the folder (`python3 -m http.server 3000` / `npx serve .`).
2. `npm run build` regenerates `config.js` from `HUBSPOT_PORTAL_ID`. It is safe to run with the var unset (writes `null`). Vercel runs this on every deploy.
3. There is **no test suite and no CI** — verification is manual: serve locally and click through every page (nav, burger menu, forms, FAQ accordion).
4. Deploy = merge to `main`; Vercel auto-deploys to www.t-shield.co.

## How to ship (mandatory guardrails)
- Own branch always. **NEVER commit straight to `main`.**
- Branch → Pull Request → eyeball-verify locally → merge.
- **NEVER force-push. NEVER `git add -A` / `git add .`** — stage explicit paths.
- Use `git -C <path> <cmd>` rather than `cd … && git`.
- **Never hand-edit `config.js`** — it is regenerated by the build. Change the HubSpot portal ID via the `HUBSPOT_PORTAL_ID` env var in Vercel, not in the file.
- Because this is the **public production site**, manually open the affected page(s) in a browser before merging. There is no CI safety net.
- The repo owner (Nabil) does the final merge to `main` on production-facing changes.

## House rules
- **Match the existing markup and styling exactly** — copy patterns from neighbouring sections/pages. No new colours, fonts, or layout idioms. Brand colours and fonts (Barlow Condensed / Barlow) are defined as CSS variables in `styles.css`; reuse them, never hard-code new hex values.
- Keep the pages **accessible** — skip links, focus styles, and ARIA hooks on nav/FAQ/collapsibles already exist; preserve them.
- **Secrets never live in a file in this repo.** The only sensitive config (HubSpot portal ID) is an env var in Vercel. A token committed here gets auto-revoked by GitHub secret-scanning.
- If you change page copy or structure that affects structured data, re-run `node scripts/inject-jsonld.js` from the repo root (it's idempotent).
- If something isn't documented, ask the repo owner — don't guess on the live public site.

## Layout + asset rules learned in production (added 2026-09-04)

- **A photo and its caption band are one unit.** Put both inside one wrapper and put any size constraint (`max-width`) on the wrapper. **Never** set `max-height` on a frame that has `aspect-ratio` — the cap transfers into the frame's width and a sibling caption band will overhang it at some viewport (TOPAZ-958, TOPAZ-961). Regression probe: `design/qa/probe.mjs` in the Drive T-Shield folder — run it at 320…1920 before shipping a layout change.
- **Replaced a file under `/assets/`? Change its URL.** Assets are served `Cache-Control: immutable, max-age=1y`; a same-name replacement never reaches a returning browser. Bump `?v=N` in every reference or use a new filename (TOPAZ-959).
- **No layout in inline styles.** An inline `grid-template-columns` (or width/aspect) can never be collapsed by a media query, so it breaks on phones (TOPAZ-965 found four). Use a class (`.g-2`, `.g-3`, `.fig-col`) with its breakpoint in the page's `<style>`.
- **Anything revealed on `:hover` needs a touch path.** Wrap the always-visible fallback in `@media (hover: none)`; never write copy that says "hover".
- **One copy of each script.** Two copies of the slider/progress code ran on the Interior page for months (double listeners). Grep for a function name before pasting a block.

## Enquiry forms (added 2026-09-05, TOPAZ-967)
- All three forms POST JSON to `api/lead.js` (Vercel serverless, Node runtime, no dependencies), which emails each submission via Resend. Env on the Vercel project: `RESEND_API_KEY` (sensitive — set in the Vercel UI, never in the repo), `LEADS_FROM` (a Resend-verified sender), `LEADS_TO` (comma-separated). Changing an env var needs a redeploy.
- Field names are the contract: `first_name`/`last_name` or `name`, `email`, `phone`, `property_type`, `vehicle`, `coverage`, `location`, `message`, `website` (honeypot — must stay empty and hidden). Adding a field = add it to the `fields` list in `api/lead.js`.
- Offline test harness pattern: require the handler, mock `global.fetch`, call with `{method, headers, body}` and a fake `res` — see TOPAZ-967 for the cases (method, origin, validation, honeypot, config, send failure).
